# Первая версия

## Границы MVP

- Все шесть сценариев S1–S6 обязательны. MVP закончен, когда они проходятся в одном демо.
- Сервис — единица с ровно одним GitHub-репозиторием. Проект объединяет несколько сервисов.
- Админской роли нет: любой сотрудник создаёт проект и приглашает людей.
- Добавлять и удалять участников можно только в проектах, где сотрудник состоит сам.
- Все участники проекта равны. Владельца и ролей нет.
- Одна текстовая инструкция на проект.
- GitHub App установлен на организацию; проект соответствует команде организации.
- Агент подключается персональным токеном сотрудника и не имеет собственных прав.
- Агент клонирует репозитории, выполняет команды установки из инструкции и проверяет доступ.

## Сценарии

### S1. Приглашение и вход сотрудника

**Цель:** новый сотрудник попадает в платформу без переписки в чате.

1. Сотрудник вводит email нового человека и отправляет приглашение.
2. Приглашённый переходит по ссылке, задаёт пароль и входит.
3. Сотрудник видит только проекты, где он участник.

**Результат:** у человека есть учётная запись и список доступных проектов.

### S2. Создание проекта и привязка репозиториев

**Цель:** проект объединяет репозитории нескольких сервисов.

1. Сотрудник создаёт проект и становится его участником.
2. Добавляет сервис и привязывает к нему GitHub-репозиторий.
3. Повторяет шаг 2 для остальных сервисов проекта.
4. Пишет инструкцию для агентов на уровне проекта.

**Результат:** проект содержит сервисы, репозитории и инструкцию.

### S3. Выдача доступа к проекту

**Цель:** сотрудник получает весь разрешённый проект целиком.

1. Участник проекта добавляет в него сотрудника.
2. Добавленный сотрудник видит проект и все его репозитории.
3. GitHub App добавляет его в команду проекта и выдаёт доступ к репозиториям.

**Результат:** членство в проекте и доступ к репозиториям на GitHub совпадают.

### S4. Подключение агента

**Цель:** агент сотрудника подключается к платформе.

1. Сотрудник получает персональный токен.
2. Передаёт токен агенту и подключает его.
3. Платформа аутентифицирует агента как действие от имени сотрудника.

**Результат:** агент подключён и не имеет прав шире прав сотрудника.

### S5. Работа агента по инструкциям

**Цель:** агент сам готовит окружение и проверяет доступ.

1. Агент запрашивает доступные проекты, репозитории и инструкции.
2. Платформа отдаёт только то, что разрешено сотруднику.
3. Агент клонирует репозитории и выполняет команды установки из инструкции.
4. Агент проверяет доступ к репозиториям и сообщает результат сотруднику.

**Результат:** сотрудник может начать работу, не выясняя вручную, что ему доступно.

### S6. Отзыв доступа при уходе

**Цель:** уволенный сотрудник и его агент теряют доступ одновременно.

1. Любой сотрудник деактивирует аккаунт уходящего.
2. Платформа закрывает вход в аккаунт.
3. Платформа убирает человека из всех проектов и команд GitHub.
4. Токен агента аннулируется; агент больше не получает данные компании.

**Результат:** ни человек, ни его агент не имеют доступа к платформе и коду.

## Карта пользовательских историй

| Деятельность | Задачи | Истории MVP |
| --- | --- | --- |
| Впустить сотрудника | пригласить → войти → увидеть свои проекты | приглашение по email; вход по ссылке; список только своих проектов |
| Завести проект | создать → добавить сервис → привязать репозиторий → написать инструкцию | создание проекта; сервис с одним репозиторием; одна инструкция на проект |
| Выдать доступ | добавить участника → увидеть репозитории → получить доступ на GitHub | добавление только в свои проекты; синхронизация с командой GitHub |
| Подключить агента | получить токен → подключить → аутентифицировать | персональный токен; агент действует от имени сотрудника |
| Работать через агента | запросить данные → подготовить окружение → проверить доступ | выдача только разрешённого; клонирование и установка по инструкции; отчёт о доступе |
| Закрыть доступ | деактивировать → закрыть вход → убрать из проектов и GitHub → аннулировать токен | одна операция деактивации; отзыв членства и токена |

## Вне MVP

Команды и роли, несколько инструкций и общие скиллы, вторая интеграция, контроль расходов на модели, агент компании, задачи в облаке и песочница, несколько агентов, аудит доступов.

## Предпосылки

- GitHub App устанавливает владелец организации — разово, вне продукта.
- Приглашения доставляются по email.
- Команда выбирает одного агента; платформа поддерживает один способ подключения.
