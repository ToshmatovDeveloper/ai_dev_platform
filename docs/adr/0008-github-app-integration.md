# Интеграция с GitHub App

S3 требует добавить сотрудника в команду проекта и выдать доступ к репозиториям. S6 требует убрать его оттуда. Документация GitHub показывает: управление командой требует Organization permissions Members write. Доступ команды к репозиторию требует Repository permissions Administration write. Приглашение по email с `team_ids` не позволяет позже менять членство без username.

## Решение

- Сотрудник вводит GitHub username при принятии приглашения.
- Платформа пытается проверить username и показать профиль. Проверка не блокирует принятие.
- Username хранится в профиле сотрудника в Identity.
- Платформа создаёт команду `aidp-<project-slug>` на проект.
- Если имя команды занято, проект создаётся, а синхронизация переходит в `failed` с понятной ошибкой.
- Команда получает право `push` на каждый репозиторий проекта.
- Один репозиторий принадлежит одному сервису в компании.
- Поддерживаются установки на все или выбранные репозитории.
- Если репозиторий вне установки, платформа показывает ошибку и просит добавить его.
- Статус синхронизации участника: `pending`, `synced`, `failed`.
- Если сотрудник ещё не в организации GitHub, GitHub отправляет приглашение. Членство остаётся `pending`, пока он не примет приглашение.
- Outbox повторяет синхронизацию. Ручной повтор добавим позже.
- Webhooks в MVP не используем.
- Installation ID находится через `GET /orgs/{org}/installation` с JWT.
- Integrations хранит установку для компании.

Права GitHub App:
- Organization permissions: Members read/write.
- Repository permissions: Administration write.
- Metadata: read.
- Contents не нужен.

Предпосылки:
- Синхронизация команд с IdP выключена.
- Владелец организации установил App.
- Для демо App можно поставить на все репозитории.

## Причины

- Username нужен для удаления и изменения членства в S6.
- Email-приглашение не даёт постоянной синхронизации.
- Префикс команды снижает риск совпадения.
- Push нужен разработчикам.
- Статус синхронизации показывает расхождение с GitHub.
- App не читает код без права Contents.

## Последствия

- Приглашение просит GitHub username.
- Неверный username блокирует синхронизацию.
- Членство в команде может быть `pending`, пока человек не примет приглашение в организацию.
- При выбранных репозиториях владелец должен добавлять новые репозитории в установку.
- При включённой синхронизации с IdP интеграция не работает.
- Webhooks и обнаружение ручных изменений появятся позже.
