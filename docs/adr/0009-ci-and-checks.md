# CI и обязательные проверки

Репозиторий на GitHub. Агент и человек работают через PR. Нужны быстрые проверки, которые ловят поломки границ, сборки и конфигурации.

## Решение

- CI: GitHub Actions.
- Обязательные проверки PR:
  - Backend: restore, build, тесты, architecture tests, проверка отсутствия неприменённых миграций.
  - Frontend: lint, typecheck, тесты, build, проверка расхождения типов OpenAPI.
  - Docker: `docker compose config`.
- Интеграционные тесты используют Testcontainers с PostgreSQL.
- GitHub в тестах заменяется фейковым адаптером. Реальные вызовы не идут.
- Кеш NuGet и npm.
- Полный Compose smoke запускается на `main` после merge или вручную.
- Branch protection на `main`: только PR, обязательные проверки, без прямого push.
- Деплоя в MVP нет.

## Причины

- Проверки ловят нарушения границ и сборки до merge.
- Testcontainers дают одинаковую базу локально и в CI.
- Фейковый GitHub делает тесты детерминированными и не требует секретов.
- Smoke на `main` сохраняет быстрый PR.
- Защита `main` совпадает с `docs/agents/agent-workflow.md`.

## Последствия

- Настройка CI и branch protection — отдельная задача.
- E2E и полный smoke на PR появятся позже.
- Проверка миграций запускается для каждого `DbContext`.
- Новые проверки добавляются отдельными задачами.
