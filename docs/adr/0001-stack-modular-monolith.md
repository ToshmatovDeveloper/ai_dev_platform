# Модульный монолит на ASP.NET Core и React

Разработчик один. У него есть опыт ASP.NET Core Web API, EF Core и PostgreSQL. Backend: ASP.NET Core Web API, EF Core, PostgreSQL. Frontend: React с Vite и TypeScript. Приложение — модульный монолит в одном процессе. Окружение — Docker Compose.

Причины: знакомый стек, один backend-процесс, сильная типизация, зрелая работа с PostgreSQL, сильная экосистема React. Микросервисы и Kubernetes добавили бы инфраструктуру без пользы для MVP.

## Рассмотренные варианты

- TypeScript на обоих концах. Меньше языков, но разработчик знает C# глубже.
- Python или Go на backend. Новая база без выгоды для MVP.
- Микросервисы. Больше операций, чем может поддержать один разработчик.

## Последствия

- Один deployable API и один frontend.
- Границы модулей держатся проектами .NET, а не сетью.
- Позже отдельный модуль можно вынести в сервис.
