# Схема на модуль, EF Core и UUIDv7

Каждый модуль владеет своей схемой PostgreSQL и своим `DbContext`. Модуль не читает и не пишет в чужие таблицы. Внешних ключей между схемами нет, связи только по ID. Все ID — UUID версии 7. Миграции EF Core — отдельные на модуль; один запуск применяет все. API миграции при старте не выполняет. Seed — отдельная идемпотентная команда.

Причины: изоляция данных на уровне схемы. UUIDv7 упорядочен по времени и лучше ложится в индекс. Отдельные миграции не блокируют модули.

## Рассмотренные варианты

- Одна схема на всё: слабее изоляция.
- Роли БД на модуль: усиление, но сложнее миграции; отложено.
- Целые ID и ULID: не берём.

## Последствия

- Больше миграций.
- Нет SQL-джойнов между схемами.
- `company_id` в каждой таблице.
