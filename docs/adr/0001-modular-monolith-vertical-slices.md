# Модульный монолит и вертикальные срезы

Контекст: одна команда, MVP, один развёртываемый процесс. Решение: модульный монолит на ASP.NET Core (.NET 10 LTS), EF Core и PostgreSQL 17. Код внутри модуля — вертикальные срезы по сценариям, без слоёв `Controllers`, `Services` и `Repositories`. Frontend — React SPA.

Причины: один процесс проще в эксплуатации. Границы модулей держит компилятор. EF Core зрело работает с PostgreSQL. Вертикальные срезы уменьшают церемонию. Микросервисы и Kubernetes добавили бы инфраструктуру без пользы для MVP.

## Рассмотренные варианты

- Микросервисы: больше операций, чем нужно для MVP.
- TypeScript на бэкенде: один язык с фронтендом, но слабее границы модулей на уровне компилятора.
- Python или Go: новая база без выгоды для MVP.

## Последствия

- Один deployable API и один frontend.
- Модуль можно вынести в сервис позже.
- Внутри модуля нет слоёв.
