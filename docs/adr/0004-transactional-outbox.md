# Транзакционный outbox

Создание сотрудника и выдача доступа — разные транзакции. Решение: каждый модуль пишет событие в свою таблицу outbox в той же транзакции, что и изменение данных. Свой фоновый диспетчер модуля читает только свою схему. Статусы: `pending`, `processed`, `failed`. Повторы с растущей паузой. Получатель идемпотентен: хранит ID обработанных событий.

Причины: согласованность без распределённой транзакции. Сбой получателя не откатывает изменение. Событие переживает перезапуск процесса.

## Рассмотренные варианты

- RabbitMQ с первого дня: отдельный сервис без второго процесса.
- Распределённая транзакция: сложно и хрупко.

## Последствия

- Межмодульные побочные действия согласованы в итоге, а не сразу.
- Нужны таблицы outbox и обработанных событий.
- Шина скрыта за `IEventBus`. RabbitMQ добавим позже.
