# Безопасность и эксплуатация MVP

MVP работает на Docker Compose. Нужны базовые защиты и надёжная синхронизация без production-операций.

## Решение

- Журнал деактивации: append-only таблица в Identity. Поля: actor, target, company, timestamp, IP, user agent. UI в MVP нет.
- Rate limit: 5 попыток в минуту на вход и приглашения. Ответ `429`.
- Очистка сессий: фоновая задача раз в день удаляет истёкшие и отозванные сессии.
- Пароли: минимум 12 символов, максимум 128, без обязательных классов. Блокировки сотрудника нет.
- Outbox: exponential backoff, максимум 10 попыток, затем `failed`.
- Seed: `GitHub:Organization` в конфиге. Seed находит installation через JWT и сохраняет в Integrations. Если установки нет, seed падает с понятной ошибкой.
- Эксплуатация MVP: без деплоя, метрик, трейсинга и алертов. Только health checks и структурные логи.

## Причины

- Журнал даёт проверяемый след деактивации.
- Rate limit заменяет блокировку сотрудника.
- Длина пароля важнее классов символов.
- Повторы переживают временные сбои GitHub.
- Seed с одним значением конфига проще ручного installation ID.
- Production-операции не нужны для демо S1–S6.

## Последствия

- UI обрабатывает `429`.
- Журнал растёт и требует стратегии хранения позже.
- После 10 ошибок нужен ручной повтор. Его добавим позже.
- Метрики, трейсинг и алерты появятся после MVP.
