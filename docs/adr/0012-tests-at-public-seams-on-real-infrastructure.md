# Тесты на публичных швах и реальной инфраструктуре

Тесты вызывают систему через публичные швы. Поведение модуля проверяется через HTTP endpoint. Интеграционные тесты используют реальную PostgreSQL 17 в Testcontainers и миграции EF Core. Подменяются только время, случайность и внешние сервисы. Правила для агентов — [docs/agents/testing.md](../agents/testing.md).

Причины: тест проверяет то, что видит вызывающая сторона. Поведение переживает рефакторинг. Реальная БД ловит ошибки SQL, ограничений, транзакций и схем. Один шов не даёт тестам обходить доступ, валидацию и Problem Details.

## Рассмотренные варианты

- Подмена `DbContext`, репозиториев, `*.Contracts` и HTTP-конвейера. Отклонено: тест проверяет внутренние вызовы, а не результат. Подмена конвейера обходит аутентификацию, CSRF, валидацию и ошибки. Тест ломается при рефакторинге и пропускает дефекты на границе. Второй шов на обработчиках и контрактах противоречит ADR 0001 и 0003.
- In-memory provider или SQLite вместо PostgreSQL. Отклонено: они не повторяют типы, ограничения, схемы, транзакции и блокировки PostgreSQL. Тест зелёный, production падает.
- Testcontainers с PostgreSQL 17. Принято: реальная версия БД, миграции EF Core, изоляция контейнера и повторяемость.

## Последствия

- Для интеграционных тестов нужен Docker. Без Docker тесты падают, а не пропускаются молча.
- Версия PostgreSQL закреплена образом 17. Смена версии — отдельное изменение.
- Respawn очищает данные перед каждым тестом. Каждый тест создаёт свои данные.
- Время берётся из `TimeProvider`; тесты подменяют его на `FakeTimeProvider`. Случайность и внешние сервисы подменяются на границе адаптера.
- В production коде нет флагов и веток для тестов. Тестовые зависимости подключаются через DI.
- Один контейнер на сборку, одна база на коллекцию. Миграции применяются один раз.
