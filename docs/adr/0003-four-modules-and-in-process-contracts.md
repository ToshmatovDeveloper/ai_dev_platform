# Четыре модуля и контракты в процессе

Нужны ясные границы. Решение: четыре модуля — Employees, Projects, AgentConnections, Access. `SharedKernel` и `Infrastructure` — общие библиотеки, не модули. Модуль ссылается на другой модуль только через `*.Contracts`. Запросы между модулями идут синхронно, через контракты. Побочные действия — через outbox.

Причины: границы не разрушаются случайно; контракты — единственная публичная поверхность. HTTP между модулями в одном процессе не нужен: он не усиливает изоляцию данных, но добавляет аутентификацию, таймауты и отказы.

## Рассмотренные варианты

- HTTP между модулями в одном процессе: лишняя сложность.
- Отдельные процессы: это уже микросервисы.
- Больше модулей: дробление без пользы для MVP.

## Последствия

- Каждый модуль — отдельный проект .NET.
- Проверку членства выполняет host через `Access.Contracts`.
- Зависимости модулей не образуют циклов.
