# Общий сервис с company_id с первого дня

Первая версия обслуживает одну компанию. В будущем платформой могут пользоваться несколько компаний. Выбран общий сервис, а не отдельная установка на компанию.

Каждая таблица, принадлежащая компании, получает `company_id`. Один сотрудник принадлежит одной компании. Вход выполняется в контексте компании. Компания — арендатор платформы.

Причины: добавить арендатора позже дорого. Нужно менять все таблицы, запросы и уникальные ограничения. Один сотрудник на компанию упрощает сценарий деактивации и вход.

## Рассмотренные варианты

- Отдельная установка на компанию. Проще данные, но хуже обновления и поддержка.
- Глобальный человек с членством в компаниях. Гибче, но сложнее вход, деактивация и права.

## Последствия

- Все запросы и уникальные ограничения учитывают `company_id`.
- Один человек в двух компаниях не поддерживается.
- Появится отдельный сценарий создания компании.
