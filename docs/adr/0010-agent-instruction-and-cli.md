# Инструкция и CLI агента

Инструкция должна быть читаемой человеком и разбираемой агентом. Агент работает на машине сотрудника и использует его GitHub-доступ.

## Решение

Формат инструкции:
- Markdown.
- Обязательный раздел `## Установка`.
- Один подраздел `### <service-name>` на сервис.
- Команды в блоках `bash`.
- Агент запускает блоки по порядку в корне репозитория сервиса.
- Текст вне раздела — для человека.
- UI даёт шаблон инструкции.
- API не парсит инструкцию. Агент сообщает об ошибке.

CLI:
- `aidp-agent` на .NET 10.
- Self-contained single-file сборки для Windows, macOS и Linux.
- Команды: `connect`, `bootstrap`, `prepare`, `check`.
- `connect` сохраняет API URL и токен.
- `bootstrap` получает проекты, репозитории и инструкции.
- `prepare --project <id>` клонирует репозитории и выполняет установку.
- `check --project <id>` проверяет доступ через `git ls-remote`.
- Токен хранится в пользовательском конфиге ОС с доступом только для пользователя (`0600` на Unix, ACL пользователя на Windows). Переопределение — `AIDP_TOKEN`.
- Рабочая папка: `./.aidp/<company>/<project>/<service>`.
- Если папка уже есть, CLI её не трогает.
- Результат печатается в stdout.
- Короткая инструкция для выбранного агента объясняет, как вызвать CLI.

## Причины

- Markdown читают люди и разбирают агенты.
- CLI делает S5 детерминированным и тестируемым.
- Любой агент, умеющий запускать команды, использует CLI.
- Личный GitHub-доступ сотрудника сохраняет правило «агент не шире сотрудника».

## Последствия

- Имена сервисов в заголовках должны совпадать с сервисами проекта.
- Существующие репозитории не обновляются автоматически.
- Ошибка команды останавливает установку и попадает в отчёт.
- Сборка бинарников под три ОС входит в релизный процесс.
