# Контракт web API

Документ фиксирует HTTP-контракт для React SPA. Архитектура — в `README.md`. Решения — в `docs/adr/`. API агента описан в `docs/adr/0007-agent-api-contract.md`.

## Общие правила

- REST и контроллеры ASP.NET Core.
- Базовый путь web API: `/api/v1`.
- API агента: `/api/agent/v1`.
- Web-аутентификация: HttpOnly-cookie и серверная сессия.
- CSRF: заголовок `X-CSRF-TOKEN` для `POST`, `PUT`, `PATCH`, `DELETE`.
- Компания берётся из сессии. Slug в URL frontend должен совпадать с сессией.
- Ошибки: Problem Details.
- Пагинации в MVP нет.
- Полного справочника сотрудников нет.
- OpenAPI-схема публикуется.

## Ошибки

Problem Details:
- `type`
- `title`
- `status`
- `detail`
- `code` — машинный код
- `errors` — ошибки полей
- `warnings` — предупреждения

Коды:
- `401` — нет сессии или неверные данные.
- `403` — нет прав.
- `404` — объект не найден или недоступен.
- `409` — конфликт.
- `410` — приглашение истекло или использовано.
- `422` — неверные данные.
- `429` — слишком много попыток.
- `503` — GitHub недоступен.

## Аутентификация и профиль

### GET /api/v1/auth/csrf

Публичный. Ставит CSRF-cookie. Возвращает токен.

### POST /api/v1/auth/login

Публичный.

Поля: `companySlug`, `email`, `password`.

Успех: `200`, cookie сессии, сотрудник и компания.

Ограничение: 5 попыток в минуту на IP+email.

Ошибки: `401` неверные данные или неактивный сотрудник; `404` компания не найдена; `429` слишком много попыток.

### POST /api/v1/auth/logout

Требует сессию. Отзывает текущую сессию. `204`.

### GET /api/v1/me

Требует сессию.

Возвращает: `employeeId`, `name`, `email`, `githubUsername`, `companyId`, `companySlug`, `companyName`.

### PATCH /api/v1/me

Требует сессию.

Поля: `githubUsername`.

Успех: `200`.

Ошибки: `409` username уже занят в компании; `422` неверный формат.

Смена username запускает повторную синхронизацию доступа.

## Приглашения

### POST /api/v1/invitations

Требует сессию. Любой активный сотрудник.

Поля: `email`.

Успех: `201`. Возвращает `invitationId`, `email`, `expiresAt`, `link`.

Правила:
- Если сотрудник уже есть в компании — `409`.
- Если есть ожидающее приглашение, старое отзывается и создаётся новое.
- Письмо уходит через outbox.
- `link` показывается как запасной путь.
- Приглашение живёт 7 дней и одноразовое.
- Ограничение: 5 запросов в минуту на сотрудника.

### GET /api/v1/invitations/{token}

Публичный.

Возвращает: `companyName`, `inviterName`, `email`, `expiresAt`.

Ошибки: `410` истекло или использовано.

### POST /api/v1/invitations/{token}/accept

Публичный.

Поля: `password`, `githubUsername`.

Успех: `201`, создаётся сотрудник, сессия и cookie.

Ошибки:
- `409` email уже занят или username занят.
- `410` приглашение недействительно.
- `422` пароль или username неверны.
- `429` слишком много попыток.

Пароль: минимум 12 символов, максимум 128. Без обязательных классов символов.

Проверка username в GitHub не блокирует принятие. Ошибка видна в статусе синхронизации.

## Проекты

### GET /api/v1/projects

Требует сессию.

Возвращает проекты, где сотрудник участник: `projectId`, `name`, `slug`, `serviceCount`, `memberCount`.

### POST /api/v1/projects

Требует сессию. Любой активный сотрудник.

Поля: `name`, `slug`.

Успех: `201`. Создатель становится участником. `syncStatus: pending`.

Ошибки: `409` slug занят; `422` неверный slug.

Slug: `^[a-z0-9][a-z0-9-]{1,62}[a-z0-9]$`, уникален в компании.

GitHub-команда: `aidp-<slug>`.

Команда создаётся асинхронно. Если имя команды занято, проект создаётся, а `githubTeam.syncStatus` становится `failed`.

### GET /api/v1/projects/{projectId}

Требует членства.

Возвращает:
- `projectId`, `name`, `slug`, `instruction`;
- `githubTeam`: `name`, `syncStatus`, `syncError`;
- `services`: `serviceId`, `name`, `repository` (`fullName`, `sshUrl`, `httpsUrl`, `syncStatus`, `syncError`);
- `members`: `employeeId`, `name`, `email`, `githubUsername`, `syncStatus`, `syncError`.

Ошибки: `404` если проект не найден или сотрудник не участник.

### PUT /api/v1/projects/{projectId}/instruction

Требует членства.

Поля: `text`.

Успех: `200`.

В MVP последняя запись побеждает.

### POST /api/v1/projects/{projectId}/members

Требует членства.

Поля: `email`.

Успех: `201` с участником и `syncStatus: pending`.

Если уже участник — `200` с текущим участником.

Ошибки: `404` сотрудник не найден в компании.

Правило: добавлять можно только в проекте, где действующий сотрудник участник.

### DELETE /api/v1/projects/{projectId}/members/{employeeId}

Требует членства.

Успех: `204`.

Ошибки: `409` если это последний участник проекта.

Правило: удалять можно только в проекте, где действующий сотрудник участник.

## Сервисы и репозитории

### POST /api/v1/projects/{projectId}/services

Требует членства.

Поля: `name`, `repositoryFullName`.

Успех: `201` с сервисом и `syncStatus: pending`.

Ошибки:
- `409` имя сервиса или репозиторий уже заняты в компании.
- `422` репозиторий не найден в установке GitHub App.
- `503` GitHub недоступен, сервис не создаётся.

Правила: один сервис — один репозиторий. Один репозиторий — один сервис в компании.

### GET /api/v1/projects/{projectId}/available-repositories?query=

Требует членства.

Возвращает репозитории установки, доступные для привязки: `fullName`, `sshUrl`, `httpsUrl`.

Ошибки: `503` GitHub недоступен.

Поиск привязан к проекту, чтобы не раскрывать имена репозиториев всем сотрудникам.

## Токены агента

### GET /api/v1/agent-tokens

Требует сессию. Только свои токены.

Возвращает: `tokenId`, `name`, `prefix`, `createdAt`, `lastUsedAt`, `expiresAt`, `revokedAt`.

### POST /api/v1/agent-tokens

Требует сессию.

Поля: `name`.

Успех: `201`. Возвращает `tokenId`, `name`, `token` один раз, `expiresAt`.

Токен: `agt_` + 32 случайных байта, срок 90 дней.

### DELETE /api/v1/agent-tokens/{tokenId}

Требует сессию. Только свой токен.

Успех: `204`.

## Деактивация

### POST /api/v1/employees/deactivate

Требует сессию. Любой активный сотрудник.

Поля: `email`, `password`, `confirm`, `force` (по умолчанию `false`).

Успех: `202`. Вход закрывается сразу. Outbox убирает из проектов, команд и отзывает токены.

Ошибки:
- `401` неверный пароль.
- `404` сотрудник не найден.
- `409` `last-member-of-projects` с `projectIds`, если сотрудник последний участник. Повторить с `force: true`.
- `204` если сотрудник уже неактивен.

Правило: деактивировать можно любого сотрудника компании, включая себя. Агент не может вызвать endpoint. Действие пишется в журнал деактивации.

Если сотрудник был последним участником проекта, проект остаётся без участников и становится недоступен. Это известное ограничение MVP.

## Правила доступа

Публичные:
- `GET /api/v1/auth/csrf`
- `POST /api/v1/auth/login`
- `GET /api/v1/invitations/{token}`
- `POST /api/v1/invitations/{token}/accept`
- `/health/*`
- `/openapi/v1.json`

Требуют сессию:
- профиль;
- создание приглашения;
- проекты;
- токены агента;
- деактивация.

Требуют членства в проекте:
- карточка проекта;
- инструкция;
- участники;
- сервисы;
- поиск репозиториев.

Только сотрудник, создавший токен:
- список, создание и отзыв токенов агента.

## Статусы синхронизации

`pending`:
- изменение принято;
- GitHub ещё не подтвердил результат.

`synced`:
- GitHub подтвердил результат.

`failed`:
- GitHub вернул ошибку;
- outbox повторил до 10 раз с backoff;
- ручной повтор появится позже;
- `syncError` содержит безопасный текст.

## Идемпотентность

- Повторное добавление участника возвращает текущего участника.
- Повторное удаление участника возвращает `204`.
- Повторная деактивация возвращает `204`.
- Повторное создание проекта с тем же slug даёт `409`.
- Повторное создание сервиса с тем же именем или репозиторием даёт `409`.

## Безопасность

- Rate limit: 5 попыток в минуту на вход и приглашения.
- Пароль: 12–128 символов.
- Сессии очищаются раз в день.
- Журнал деактивации хранится в Identity.
