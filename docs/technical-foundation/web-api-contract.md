# Контракт API

Документ фиксирует общие правила HTTP API. Детали endpoint модулей добавляются при проектировании модулей. Архитектура — `README.md`. Решения — `docs/adr/`.

## Общие правила

- REST. Web API: `/api/v1`. API агента: `/api/agent/v1`.
- Версия стоит в пути.
- Web-аутентификация: HttpOnly-cookie и серверная сессия.
- CSRF: заголовок `X-CSRF-TOKEN` для `POST`, `PUT`, `PATCH`, `DELETE`.
- Компания берётся из сессии. Slug в URL фронтенда должен совпадать с сессией.
- Ошибки: Problem Details.
- Пагинации в MVP нет.
- OpenAPI-схема публикуется.
- Один origin: Vite проксирует `/api` в разработке, Nginx — в production.
- Формат: JSON, `camelCase`. Даты — ISO 8601 в UTC. ID — UUID версии 7 строкой.

## Ошибки

Problem Details:

- `type`;
- `title`;
- `status`;
- `detail`;
- `code` — машинный код;
- `errors` — ошибки полей.

Коды HTTP:

- `401` — нет сессии или неверные данные.
- `403` — нет прав.
- `404` — объект не найден или недоступен.
- `409` — конфликт.
- `410` — приглашение истекло или использовано.
- `422` — неверные данные.
- `429` — слишком много попыток.
- `503` — внешний сервис недоступен.

## Аутентификация и профиль

### GET /api/v1/auth/csrf

Публичный. Ставит CSRF-cookie. Возвращает токен.

### POST /api/v1/auth/login

Публичный.

Поля: `companySlug`, `email`, `password`.

Успех: `200`, cookie сессии, сотрудник и компания.

Ошибки: `401` неверные данные или неактивный сотрудник; `404` компания не найдена; `429` слишком много попыток.

### POST /api/v1/auth/logout

Требует сессию. Отзывает текущую сессию. `204`.

### GET /api/v1/me

Требует сессию.

Возвращает: `employeeId`, `name`, `email`, `githubUsername`, `companyId`, `companySlug`, `companyName`.

### PATCH /api/v1/me

Требует сессию.

Поля: `githubUsername`.

Успех: `200`.

Ошибки: `409` username уже занят в компании; `422` неверный формат.

## Статус и здоровье

### GET /health/live

Публичный. Проверка процесса.

### GET /health/ready

Публичный. Проверка соединения с PostgreSQL.

### GET /api/v1/status

Публичный. Проверка БД для тестовой страницы. Возвращает версию API, статус БД и время.

### GET /openapi/v1.json

Публичный. OpenAPI-схема web API.

## API агента

### GET /api/agent/v1/bootstrap

Требует Bearer-токен агента. Только чтение.

Возвращает компанию, проекты, сервисы, репозитории (`fullName`, `sshUrl`, `httpsUrl`), инструкции и GitHub username сотрудника.

Возвращает только то, что разрешено сотруднику: проекты, где он участник.

Ошибки: `401` неверный или отозванный токен; `403` сотрудник неактивен; `404` данные недоступны.

Пагинации нет. Web-сессия не может вызывать API агента.

## Правила доступа

Публичные:

- `GET /api/v1/auth/csrf`;
- `POST /api/v1/auth/login`;
- `GET /health/*`;
- `GET /api/v1/status`;
- `GET /openapi/v1.json`.

Требуют сессию:

- профиль;
- приглашения;
- проекты;
- токены агента;
- деактивация.

Требуют членства в проекте:

- карточка проекта;
- инструкция;
- участники;
- сервисы;
- поиск репозиториев.

Только сотрудник, создавший токен:

- список, создание и отзыв своих токенов агента.

API агента требует только Bearer-токен агента.

## Версионирование

- Ломающие изменения — новая версия в пути.
- Совместимые добавления — в текущей версии.
- API агента версионируется отдельно от web API.

## Endpoint модулей

Endpoint модулей добавляются при проектировании модулей:

- Employees: приглашения, сотрудники, деактивация;
- Projects: проекты, сервисы, репозитории, инструкции;
- Access: участники проекта, синхронизация доступа;
- AgentConnections: токены агента.
