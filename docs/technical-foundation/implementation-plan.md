# План реализации MVP

Цель MVP — пройти сценарии S1–S6 в одном демо. Каждый срез даёт работающий результат. Детали модулей определяются при их проектировании.

## Срез 0. Foundation

Состав:

- скелет репозитория: `apps/api`, `apps/web`, `src/modules`, `src/shared`, `infra`;
- решение .NET, приложение React, Docker Compose: `db` и `mailhog`;
- EF Core миграции и one-shot команда применения;
- seed компании и приглашения первого сотрудника;
- health checks, `GET /api/v1/status`, страница `/status`;
- OpenAPI.

Приёмка:

- `docker compose up` поднимает окружение;
- `/health/ready` отвечает;
- `/status` показывает зелёный результат и проверяет БД;
- seed создаёт компанию и приглашение.

## Срез 1. S1 — приглашение и вход

Модуль: Employees.

Состав:

- компания, сотрудник, приглашение;
- принятие приглашения, пароль, GitHub username;
- сессии, CSRF, вход и выход;
- экраны входа и принятия приглашения.

Приёмка:

- сотрудник приглашает по email;
- письмо видно в MailHog, ссылка работает;
- приглашённый задаёт пароль и GitHub username;
- вход создаёт сессию;
- сотрудник видит пустой список проектов.

## Срез 2. S2 — проект, сервисы, репозитории, инструкция

Модуль: Projects.

Состав:

- проект, сервис, привязка репозитория, инструкция;
- создание проекта;
- привязка репозитория к сервису;
- редактор инструкции.

Приёмка:

- проект создаётся;
- сервис привязывает один репозиторий;
- инструкция сохраняется.

## Срез 3. S3 — доступ к проекту и GitHub

Модуль: Access.

Состав:

- участие сотрудника в проекте;
- установка GitHub App;
- команда `aidp-<project-slug>` и право `write`;
- синхронизация через outbox;
- добавление и удаление участника.

Приёмка:

- добавленный сотрудник видит проект;
- GitHub добавляет его в команду;
- удаление убирает его из команды;
- ошибки синхронизации видны как `failed`.

## Срез 4. S4 — подключение агента

Модуль: AgentConnections.

Состав:

- создание, список и отзыв токенов агента;
- endpoint `GET /api/agent/v1/bootstrap`;
- экран токенов в профиле.

Приёмка:

- токен показывается один раз;
- список показывает префикс, срок и последнее использование;
- отзыв действует со следующего запроса;
- bootstrap отдаёт только разрешённые проекты;
- web-сессия не может вызывать API агента.

## Срез 5. S5 — работа агента по инструкциям

Состав:

- CLI агента;
- подключение по токену и получение bootstrap;
- разбор инструкции;
- рабочая папка и клонирование;
- проверка доступа.

Приёмка:

- CLI подключается по токену;
- получает проекты, репозитории и инструкции;
- клонирует отсутствующие репозитории;
- выполняет команды установки по порядку;
- проверяет доступ через `git ls-remote`;
- печатает отчёт.

## Срез 6. S6 — деактивация

Модули: Employees, Access, AgentConnections.

Состав:

- деактивация сотрудника;
- закрытие входа, отзыв сессий и токенов;
- удаление из проектов и команд GitHub;
- журнал деактивации.

Приёмка:

- вход закрывается сразу;
- сессии и токены отозваны;
- сотрудник удалён из проектов и команд;
- действие попадает в журнал.

## Срез 7. Hardening

Состав:

- повторы outbox и статус `failed`;
- обработка ошибок и `429`;
- очистка сессий;
- сквозная проверка S1–S6.

Приёмка:

- временный сбой GitHub восстанавливается;
- постоянный сбой виден как `failed`;
- rate limit отвечает `429`;
- очистка сессий работает.

## Зависимости

- Срез 1 зависит от 0.
- Срез 2 зависит от 1.
- Срез 3 зависит от 2.
- Срез 4 зависит от 1.
- Срез 5 зависит от 4.
- Срез 6 зависит от 3 и 4.
- Hardening зависит от всех срезов.

## Трекер

- Каждый срез — задача или набор задач в GitHub.
- В задаче есть результат и критерии приёмки.
- Задачи идут по `docs/agents/agent-workflow.md`.
