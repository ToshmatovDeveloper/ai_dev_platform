# План реализации MVP

Цель MVP — пройти S1–S6 в одном демо. Каждый срез даёт работающий результат. Срез становится задачей или набором задач в трекере.

## Срез 0. Foundation

Состав:
- скелет репозитория: `apps/web`, `apps/api`, `src/modules`, `src/shared`, `tests`, `infra`;
- решение .NET, приложение React, Docker Compose: `db`, `migrate`, `api`, `web`, `mailhog`;
- health checks, миграции, seed;
- CI и branch protection;
- OpenAPI.

Приёмка:
- `docker compose up` поднимает окружение;
- `/health/ready` отвечает;
- seed создаёт компанию и приглашение;
- CI зелёный.

## Срез 1. S1 — приглашение и вход

Состав:
- Companies и Identity;
- приглашение, принятие, пароль, GitHub username;
- сессии, CSRF, вход и выход;
- экраны входа и принятия приглашения.

Приёмка:
- сотрудник приглашает по email;
- письмо видно в MailHog, ссылка работает;
- приглашённый задаёт пароль и GitHub username;
- вход создаёт сессию;
- сотрудник видит пустой список проектов.

## Срез 2. S2 — проект, сервисы, репозитории, инструкция

Состав:
- Projects;
- создание проекта и команды `aidp-<slug>`;
- сервис и привязка репозитория;
- поиск репозиториев установки;
- редактор инструкции;
- статусы синхронизации.

Приёмка:
- проект создаётся, команда GitHub появляется;
- сервис привязывает репозиторий;
- команда получает `push`;
- инструкция сохраняется;
- ошибки GitHub видны как `failed`.

## Срез 3. S3 — добавление участника

Состав:
- добавление по email;
- членство в команде GitHub;
- удаление участника;
- запрет удаления последнего участника;
- экраны участников.

Приёмка:
- добавленный сотрудник видит проект;
- GitHub добавляет его в команду;
- удаление убирает его из команды;
- последнего участника удалить нельзя.

## Срез 4. S4 — токен агента

Состав:
- Agents;
- создание, список и отзыв токенов;
- endpoint `/api/agent/v1/bootstrap`;
- экран токенов в профиле.

Приёмка:
- токен показывается один раз;
- список показывает префикс, срок и последнее использование;
- отзыв действует со следующего запроса;
- bootstrap отдаёт только разрешённые проекты;
- web-сессия не может вызывать agent API.

## Срез 5. S5 — CLI агента

Состав:
- `aidp-agent` на .NET;
- `connect`, `bootstrap`, `prepare`, `check`;
- разбор инструкции;
- рабочая папка и клонирование;
- проверка доступа.

Приёмка:
- CLI подключается по токену;
- получает проекты, репозитории и инструкции;
- клонирует отсутствующие репозитории;
- выполняет команды установки по порядку;
- проверяет доступ через `git ls-remote`;
- печатает отчёт.

## Срез 6. S6 — деактивация

Состав:
- деактивация по email с паролем;
- журнал деактивации;
- отзыв сессий и токенов;
- удаление из проектов и команд GitHub;
- предупреждение о последнем участнике и `force`;
- экран деактивации.

Приёмка:
- вход закрывается сразу;
- сессии и токены отозваны;
- сотрудник удалён из проектов и команд;
- последний участник требует `force`;
- действие попадает в журнал.

## Срез 7. Hardening

Состав:
- повторы outbox и статус `failed`;
- обработка ошибок и `429`;
- очистка сессий;
- E2E S1–S6;
- проверки документации и контрактов.

Приёмка:
- E2E проходит S1–S6;
- временный сбой GitHub восстанавливается;
- постоянный сбой виден как `failed`;
- rate limit отвечает `429`;
- очистка сессий работает.

## Зависимости

- Срез 1 зависит от 0.
- Срез 2 зависит от 1.
- Срез 3 зависит от 2.
- Срез 4 зависит от 1.
- Срез 5 зависит от 4.
- Срез 6 зависит от 3 и 4.
- Hardening зависит от всех срезов.

## Проверки

- Каждый срез получает unit и integration тесты.
- GitHub в тестах заменяется фейковым адаптером.
- Integration тесты используют Testcontainers.
- E2E S1–S6 добавляется в hardening.

## Трекер

- Каждый срез — задача или набор задач в GitHub.
- В задаче есть результат и критерии приёмки.
- Задачи идут по `docs/agents/agent-workflow.md`.
