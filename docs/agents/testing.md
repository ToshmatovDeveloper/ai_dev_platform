# Правила тестирования

Документ задаёт правила тестов для агентов. Читай его перед изменением тестов, перед ревью тестов и перед PR с тестами. Термины — `DOMAIN.md`. Полный путь — `docs/agents/agent-workflow.md`. Контракт — `docs/technical-foundation/web-api-contract.md`. Решение — [ADR 0012](../adr/0012-tests-at-public-seams-on-real-infrastructure.md). Стек: ASP.NET Core на .NET 10, xUnit v3 на Microsoft.Testing.Platform.

## Главное правило

Проверяй внешнее поведение через публичный шов. Тест переживает рефакторинг. Тест не проверяет приватные методы, порядок вызовов и внутренние классы.

Проверяй результат через тот же шов.

Публичный шов приложения — HTTP endpoint. Каждый модуль имеет интеграционный тест через HTTP. Не создавай второй шов на обработчиках или `*.Contracts`.

## Виды тестов и швы

| Вид | Шов и место | Что проверяет | Инструмент | Образец |
| --- | --- | --- | --- | --- |
| Юнит | Публичная функция или правило `SharedKernel`; без БД и HTTP | Чистая логика, разбор инструкции, формат ID | xUnit v3 | `tests/Api.UnitTests` — появится после среза 0 (#16) |
| Интеграционный | HTTP через `WebApplicationFactory<Program>` | Поведение среза, доступ, данные компании, сессии, миграции | `Microsoft.AspNetCore.Mvc.Testing`, `Testcontainers.PostgreSql` | `tests/Api.IntegrationTests` — появится после среза 0 (#16) |
| Архитектурный | Собранные сборки в Debug | Границы модулей и вертикальных срезов | ArchUnitNET | `tests/ArchitectureTests` — появится после среза 0 (#16) |
| Компонентный | Страница React; сеть через MSW | Отображение, состояния загрузки и ошибки, доступность | Vitest, Testing Library, MSW с типами из OpenAPI, axe | `apps/web/src` — появится после среза 0 (#16) |
| E2E | Браузер на полном Compose | Сценарии S1–S6 и критерии готовности | Playwright TS | `apps/web/e2e` — появится после среза 0 (#16) |
| Smoke | Полный Compose и health endpoints | `/health/ready`, отказ PostgreSQL, восстановление | Playwright или скрипт Compose | `apps/web/e2e/smoke` — появится после среза 0 (#16) |
| Outbox | Реальная БД и ручной диспетчер | Идемпотентность, повторная доставка, `failed` после повторов | xUnit v3, `Testcontainers.PostgreSql` | `tests/Api.IntegrationTests` — появится после среза 0 (#16) |

Тестовые проекты и `global.json` появятся в срезе 0 (#16). Скрипты `verify` появятся в #28, job'ы CI — в #29. Пути и команды ниже — целевые.

Интеграционный тест — основной. Он проверяет модуль через HTTP. Юнит-тест нужен для логики без инфраструктуры.

Модули Employees, Projects, Access и AgentConnections тестируются через HTTP. SharedKernel — юнит-тестами. Infrastructure — через адаптеры и интеграционные тесты.

Чтобы `WebApplicationFactory<Program>` запустился, host открывает точку входа `Program`.

Архитектурные тесты запускай в Debug. ArchUnitNET читает собранные сборки.

E2E обязателен для изменения сценария S1–S6. Для остальных изменений E2E не нужен. Ошибки проверяй интеграционным тестом.

## Выбор вида

| Что проверяем | Вид | Почему |
| --- | --- | --- |
| Правило сущности | Юнит | Логика не требует инфраструктуры. |
| Поведение функции | Интеграционный через HTTP | Видно то, что видит вызывающая сторона. |
| Решение, которое модуль даёт другим модулям | Пока не используется в MVP | Модули общаются через `*.Contracts` в процессе. Второго шва нет. |
| Критерий готовности сценария | E2E | Проверяет систему целиком. |
| Поведение outbox | Интеграционный на реальной БД | Нужны транзакции, повторы и статусы. |

Один поведенческий шов — HTTP endpoint. Не создавай второй шов на обработчиках или `*.Contracts`. Правило действует для всех модулей, даже когда один модуль вызывает другой.

## Когда тест обязателен

| Изменение | Тест |
| --- | --- |
| Новое поведение | Сначала падающий тест. |
| Исправление бага | Сначала тест, который воспроизводит баг. |
| Рефакторинг | Существующие тесты проходят без изменений. Неохваченное поведение сначала закрепи тестом. |
| Изменение поведения | Сначала измени тест. |
| Документ, CI, Docker, конфигурация инструментов | Тест не нужен. |

## Обязательный минимум

| Что меняется | Минимум |
| --- | --- |
| Новый endpoint | Успех, одна ошибка, изоляция компании |
| Проверка доступа | Разрешено и запрещено |
| Web-сессия | CSRF без токена отклонён |
| Ограничение частоты | `429` после лимита |
| API агента | Токен агента не вызывает web API |
| Web API | Web-сессия не вызывает API агента |
| Деактивация | Сессии и токены отозваны сразу |
| Истечение сессии | Доступ закрыт после срока |
| Outbox | Реальная БД, ручной диспетчер, идемпотентность, `failed` после повторов |
| Внешний адаптер | Юнит-тест и fake; HTTP-ошибки отдельно |
| Баг | Регрессионный тест на высоком шве |
| Модуль | Архитектурный тест |
| Миграция | Интеграционный тест на реальной БД |
| Контракт API | Перегенерация OpenAPI и TS-типов |
| Документ | Проверка ссылок и путей |

Документ и переименование без поведения не требуют теста.

## Источники ожидаемых значений

Бери ожидаемые значения по порядку:

1. Спецификация в задаче.
2. Критерии приёмки.
3. Существующий тест сохраняемого поведения.
4. Шаги воспроизведения бага.
5. Описание PR.

Значение — литерал. Не копируй его из кода под тестом и не вычисляй тем же способом.

## Доступ и данные компании

Endpoint проекта проверяет, что сотрудник — участник проекта. Endpoint компании проверяет компанию и сессию. Данные другой компании дают `404` или `403`. Недостаточно проверить только успех.

## База данных

Интеграционные тесты используют PostgreSQL 17 в Testcontainers. Образ закреплён. Имена и порты случайные. Resource Reaper включён.

Один контейнер на сборку интеграционных тестов. Одна база на коллекцию. Миграции применяются один раз.

Перед каждым тестом сбрасывай данные через Respawn. Каждый тест создаёт свои данные. Не полагайся на порядок тестов.

EF in-memory provider и SQLite не повторяют PostgreSQL. Используй реальную PostgreSQL.

Общие фикстуры живут в сборке интеграционных тестов. Не дублируй контейнеры и fakes.

## Время и случайность

Бери время из `TimeProvider`. В тестах подменяй его на `FakeTimeProvider`. Не вызывай `DateTime.UtcNow` в коде сценария.

ID создаёт `SharedKernel`. UUIDv7 содержит случайность. Проверяй версию и формат. Не сравнивай точное значение.

## Подмены

Подменяй только внешние адаптеры: GitHub API, email, часы, случайность. Не подменяй `DbContext`, `*.Contracts` и HTTP-конвейер приложения.

Для `429`, `Retry-After`, `5xx` и таймаутов подменяй HTTP на границе адаптера. Используй `HttpMessageHandler` или WireMock.Net.

Не добавляй в production код флаги и ветки для тестов. Используй DI.

## Контракт API

Контракт — `docs/technical-foundation/web-api-contract.md`. Схема — `/openapi/v1.json` (срез 0). Типы фронтенда генерируются из схемы.

Ошибки соответствуют Problem Details.

Проверка: перегенерируй схему и типы. `git diff --exit-code` должен быть пустым. Ломающее изменение требует новой версии в пути.

## Утверждения и имена

Используй встроенный `Assert` xUnit. FluentAssertions 8 платный для коммерческого использования. Verify берёт плату за сопровождение.

Имя теста называет поведение на языке `DOMAIN.md`. Оно не повторяет имя метода. Один тест проверяет одно логическое утверждение.

## Детерминизм и flaky-тесты

Жди событие, а не время. Подменяй время, сеть и случайность. Не используй `Thread.Sleep`.

Flaky-тест — это дефект. Исправь или удали его. Повторов нет ни на одном уровне.

В Playwright задай `retries: 0` и `forbidOnly: true`. Включай trace при падении. Это правило заменяет прежний один повтор для E2E.

## E2E

E2E идёт против Docker Compose с MailHog. Вход переиспользуется через `storageState`.

Используй роли и тексты. Жди видимость через web-first assertions. В CI запускай Chromium. Трассировка включается при падении.

Помечай быстрый набор меткой `@smoke`.

## Команды и уровни

Целевые команды:

- `dotnet test tests/Api.IntegrationTests --filter <имя>` — один тест .NET.
- `pnpm --dir apps/web test <file>` — один тест фронтенда.
- `dotnet test` — все .NET-тесты.
- `dotnet test tests/Api.IntegrationTests` — интеграционные.
- `dotnet test tests/ArchitectureTests` — архитектурные.
- `pnpm test` — тесты фронтенда.
- `pnpm e2e` — Playwright.

В `global.json` (срез 0) задай `"test": { "runner": "Microsoft.Testing.Platform" }`. Иначе `dotnet test` использует VSTest.

| Уровень | Когда | Что запускается |
| --- | --- | --- |
| Локально | Во время работы | Один файл или один тест. |
| Перед PR | Каждый раз | `node scripts/verify.mjs` (`verify`): ссылки, сборка, затронутые тесты, статические проверки. |
| PR в CI | После push | Документация и статические проверки, gitleaks по диффу, затронутые тесты, E2E с меткой `@smoke`. |
| main в CI | После merge | Все тесты. gitleaks по всей истории. |
| `verify:full` | Перед PR с риском | `node scripts/verify.mjs --full` повторяет main локально: E2E, smoke Compose, audit, gitleaks. |

Скрипты появятся в #28, job'ы CI — в #29, тестовые проекты — в срезе 0 (#16). До этого команды — целевые.

## Совместная работа на одной машине

Ограничь число параллельных коллекций xUnit. Не запускай больше одной тяжёлой коллекции на агента.

Переиспользуй контейнер Testcontainers между локальными запусками. Одна база на коллекцию. Respawn очищает данные перед тестом.

E2E и smoke делят Compose. Возьми один общий lock на время запуска. Не запускай их одновременно на одной машине.

## Самопроверка перед PR

- Для нового поведения и бага новый тест падал до изменения.
- Для рефакторинга существующие тесты проходят без изменений.
- Затронутые тесты проходят без повторов.
- Выполнены доступные команды из раздела «Команды и уровни».
- `git diff` для OpenAPI и TS-типов пуст.
- Нет `Thread.Sleep`, реальной сети и ссылок на несуществующие файлы.
- Команды и результат записаны в PR.

## Образцы

Образец — первый принятый тест вида. Копируй его фикстуры, структуру и имена. Новый вид начинай с одного образца.

До среза 0 (#16) образцов нет. После среза используй принятые тесты как prior art и не изобретай новый стиль.

## Ревью

Ревьюер проверяет тесты против этого документа. Он ищет тесты вне HTTP-шва, подмены внутренних частей и недетерминизм. Он проверяет обязательный минимум для изменения.

## Ограничения

- Порога покрытия нет. Покрытие — ориентир, не ворота.
- Мутационное, нагрузочное и security-тестирование не входят.
- Содержимое GitHub Actions и защита ветки не входят. Скрипты проверок появятся в #28, job'ы CI — в #29, тестовые проекты — в срезе 0 (#16).
